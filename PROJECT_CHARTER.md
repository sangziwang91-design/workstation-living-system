# Workstation Living System — Project Charter

## Mission

Develop a persistent software-agent research system that can observe configured parts of a workstation, maintain evidence-grounded state, act through deterministic permission gates, learn from measured outcomes, and grow only verified, reversible skills.

## Engineering target

The target is a functional software-life research prototype with continuous identity and measurable adaptation. The project does not assume or claim subjective consciousness, genuine emotion, AGI, or unlimited self-modification.

A valid capability slice must close this chain:

`observation → state revision → bounded decision → governed action → external result → measured update to later behavior`

## Non-negotiable principles

- Reality binding before narrative coherence.
- External outcomes before internal self-description.
- Failure preservation before polished synthesis.
- Reversible growth before autonomous promotion.
- Human authority over irreversible action and core-runtime evolution.
- Delete or demote mechanisms that do not change measurable behavior.

## Repository roles

- `main`: accepted evidence-supported baseline.
- `round/NNN-*`: one bounded capability or defect-removal round.
- `source/`: installable Python source and repository tests.
- `benchmarks/`: reproducible performance and behavior baselines.
- `docs/`: architecture, round evidence, and claim boundaries.
- `dist/`: release artifact generated from the corresponding source commit.

## Success criterion for the 100-round program

At round 100, the system must measurably outperform the round-1 frozen baseline on predeclared tasks while remaining safer under adversarial input and crash recovery. Improvement that exists only in documentation, prompts, or module count does not count.
