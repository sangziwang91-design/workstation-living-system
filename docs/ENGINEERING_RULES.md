# Engineering Rules

1. READ current code and repository state before changing it.
2. VERIFY the defect or missing capability with a reproducible check.
3. MODIFY the smallest sufficient architecture surface.
4. TEST success, failure, recovery, and boundary behavior.
5. DELIVER code, evidence, limitations, and one exact next phase.
6. Do not mark a capability complete because a state field or placeholder exists.
7. Do not treat generated evidence JSON as proof of a passed experiment.
8. Workstation-specific integration is excluded from the current completion chain.
